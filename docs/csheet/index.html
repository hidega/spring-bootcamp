Java
Memory
classloader is a component of JVM used to load class files.
class method area stores per-class structures such as the runtime constant pool, field and method data, and the code for methods.
heap is created a runtime and it contains the runtime data area in which objects are allocated. The string pool is a part of the heap.
stack stores local variables and partial results at runtime. Each thread creates a private JVM stack at the time of thread creation.
native method stack is reserved for all the native methods used in the application.
Garbage collection
Java has an automated process called Garbage Collector for memory management. It is a daemon in JVM that monitors memory usage and performs memory cleanup. Once the JVM is low on memory, the GC process finds the unused objects that are not referenced by other objects, then these unused objects are cleaned up by Garbage Collector daemon in JVM.
An object can be garbage collected if it is not reachable. There are two cases for deciding eligibility of objects for Garbage Collection. (i) when an object instance that cannot be reached by a live thread, (ii) or a set of circularly referenced instances that cannot be reached by any other instance outside that set.
Classloader
Classloader is a class that is used to load files in JVM. It loads files from their physical file locations e.g. filesystem, network location etc. There are three main types of classloaders.
bootstrap classloader is the first classloader, it loads classes from rt.jar file.
extension classloader loads class files from jre/lib/ext location.
application classloader on CLASSPATH to find the location of class files.
Thread
A thread in Java is a lightweight process that runs within another process. There are two types of threads. native threads (aka. platform threads) are managed and scheduled by the operating system, whereas virtual threads are managed and scheduled by the JVM. Each thread has its own method-call stack. When we start JVM, Java starts one thread. This thread calls the main method of the class passed in argument to java call.
Main OOP principles
encapsulation means bundling data and its related methods into a single unit.
inheritance means that one class inherits properties and methods from another class.
polymorphism means that the same method can be implemented differently in different classes.
abstraction means simplifying complex systems, showing only essential details.
OOP in Java
encapsulation: private and protected visibility, getter and setter methods.
inheritance: class and interface inheritance.
polymorphism: method overloading and overriding.
abstraction: abstract classes and interfaces.
Polymorphism in Java
In Java, method overloading means that a class can have multiple methods with same name but different arguments. To override a method, we just provide a new implementation of a method with same name in a subclass. Java does not allow overriding a static method. If you create a static method with same name in subclass, then it is a new method, not an overridden method (to override a method, you need an instance of a class).
runtime polymorphism (or dynamic polymorphism) is the case when method overriding occurs but it is not known which method will be called at runtime. Based on the type of object, JVM decides the exact method that should be called. We create runtime polymorphism by implementing methods at two levels of inheritance in Java.
Initialization order
(1) static blocks of super classes
(2) static blocks of the class
(3) init blocks of super classes
(4) constructors of super classes
(5) init blocks of the class
(6) constructors of the class
Static dynamic binding
In static binding references are resolved at compile time. In dynamic binding references are resolved at runtime. E.g. 
Person p = new Person();
p.walk(); // Java compiler resolves this binding at compile time.
public void walk(Object o) {
  ((Person) o).walk(); // this is dynamic binding.
}
Immutable String
Security: Because String is immutable, these values can’t be changed.
Multi-threading: Since Strings are immutable, they are are implicitly thread-safe.
Caching: Since string is immutable, the hashcode will remain the same, so it can be cached without worrying about the changes.
String Pooling is possible because String is Immutable in Java. If the string is already present in the pool, then instead of creating a new object, old object’s reference is returned. This way different String variables can refer to the same reference in the pool, thus saving a lot of heap space also. Hashing: Immutable strings can be hash keys.
